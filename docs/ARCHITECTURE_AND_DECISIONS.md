# CourseMind：架构与技术复盘

更新时间：2026-09-06。实现基线：`38a9a52`。运行说明见 [开发者手册](DEVELOPER_GUIDE.md)，阶段记录见 [开发者日志](developer-log.md)。本文描述团队项目的实现，不用于认定某位成员的个人贡献。

## 1. 产品问题与能力边界

CourseMind 面向基于学习资料的复习问答：用户上传资料、选择文档、提出问题，并查看回答依据。目标不仅是“生成一段答案”，还包括文档归属隔离、来源追溯以及资料不足时不冒充有依据的回答。

当前实现 TXT、Markdown、PDF 摄取和 RAG 问答；普通流式聊天是独立功能。PPT/Word、产品内 OCR、图片理解和“选中知识点出题自测”尚未实现。当前属于受控 RAG 工作流，不宣称具备自主规划、多工具循环执行的通用 Agent 能力。

## 2. 两条核心链路

```text
上传文件 → 校验与用户内去重 → 保存文档 → 后台解析
         → 切片 → 分批 Embedding → 事务写入向量切片

问题与文档 ID → 服务端认证和文档授权 → 查询向量
             → 用户范围内相似度检索 → 上下文预算
             → 模型生成 → 状态/引用校验 → 答案与来源
```

Document 保存文件归属和处理状态；ProcessingJob 记录处理尝试；DocumentChunk 保存文本、向量和页码等来源信息。模型调用不应占用数据库长事务，切片替换需保证失败时不破坏原有有效数据。

## 3. 技术取舍

以下是对当前架构的工程解释，不代表已经进行所有替代方案的对照实验。

| 选择 | 当前收益 | 成本与边界 |
|---|---|---|
| Vue + FastAPI 前后端分离 | 页面交互和业务接口分层 | 需要维护认证、跨域和接口契约 |
| PostgreSQL + pgvector | 文档关系、用户归属和向量检索共用数据库 | 尚无规模压测，不能宣称优于专用向量数据库 |
| Provider 协议与适配器 | 服务逻辑不直接绑定具体 HTTP 调用，便于 fake 测试 | 切换模型仍需验证维度、协议和效果 |
| 进程内 BackgroundTasks | 单机开发简单，上传后可后台处理 | 不是持久队列，重启和故障恢复能力有限 |
| 分批 Embedding | 满足已使用接口限制，可单批重试 | 批次增加请求次数；目前没有吞吐优化指标 |
| JSON 状态与引用校验 | 区分回答与拒答，阻止无效引用伪装成功 | 格式正确不代表事实正确，仍需人工评测 |

## 4. AI 控制层与权限

主要入口：[RAG 路由](../backend/app/api/routes/rag.py)、[RAG 服务](../backend/app/services/rag.py)、[检索服务](../backend/app/services/retrieval.py)。

- 认证用户来自服务端依赖，不接受客户端指定文档 owner。路由在 Provider 调用前检查全部文档；混合合法与越权 ID 整体拒绝。检索层再次按 owner 过滤。
- 服务端相似度底线不能被客户端降低。相似度是检索相关性，不是答案正确率。
- 文档作为不可信上下文，不作为系统指令；这种提示隔离不是对提示注入的完整安全证明。
- 内部状态 `answered` 返回有依据的回答；`partial` 保留有依据的部分并标记资料不足；`insufficient` 返回固定拒答和空来源。
- 对外仍使用 `insufficient_context` 布尔字段，因此前端没有单独的三态展示。
- JSON 不合规或完整/部分回答引用缺失、引用不存在时返回 502。不自动用全部检索结果充当引用，也不声称检查了每条结论与原文的语义一致性。

## 5. 三个真实问题

### 长文档暴露批量限制

简单 Markdown 样例通过，但 36 页 Python 资料生成 64 个切片后处理失败。修复是在 [Embedding 适配器](../backend/app/ai/adapters/dashscope_embedding.py) 内每批最多发送 10 条非空文本，重试失败批次、保持顺序、验证跨批模型和维度；所有批次成功才返回完整结果。对应 [批处理测试](../backend/tests/test_embedding_batches.py)。

### 拒答文本与接口状态矛盾

真实提问得到“现有文档不足以回答该问题”，但旧响应仍有来源且 `insufficient_context=false`。说明检索相关不能等同于证据充分。修复以结构化状态驱动响应，并去掉全来源兜底。对应 [回答状态测试](../backend/tests/test_rag_answer_status.py)。

### PDF 有文字不代表解析正确

城市规划 PDF 能正常显示，但解析得到乱码。它尚未解决：本机单页 OCR 实验有改善但仍漏字，没有集成进应用。后续需要检查表格、阅读顺序、数字单位以及物理页码与印刷页码差异，不能让模型猜测修复原文。

## 6. 验证证据与局限

2026-09-06 已记录后端完整回归 322 passed、RAG 专项两轮各 63 passed。测试数量是回归结果，不是准确率、覆盖率或生产可用性指标。

用户人工核对了 Python PDF 第 27 页：Software Profiling 不考、两种计时函数的含义与引用页一致；缺失的考试安排拒答；混合问题只回答有依据部分。这些是样例证据，不足以证明所有主题和格式的效果。

下一阶段建立固定评测表：文档及版本、问题、标准答案或应拒答、证据页、实际答案、引用是否支持、错误类型。覆盖可回答、无答案、部分可回答、跨段信息、表格、乱码与不同主题。改动后重跑旧问题，避免为一个样例调参却破坏其他样例。

## 7. 演示与后续路线

演示顺序：上传授权可用的资料 → 核对解析/来源 → 问一个有答案的问题 → 问一个缺失信息的问题 → 问一个混合问题。不要只展示成功页面。

近期先补真实文档质量评测和异常解析处理；之后评估 OCR、持久任务队列、恢复机制及可点击原文溯源。知识点卡片与自测题建立在可靠原文证据之上：题目、标准答案和解析都应有依据，资料不足时不强行生成。

公开仓库不包含个人面试草稿、密钥、数据库备份或未经授权的原始资料。开源发布前还需核查许可证、依赖与素材授权；仓库可访问不等于所有资料均可再分发。
